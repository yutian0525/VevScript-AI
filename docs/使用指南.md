# 织雀AI脚本（Vevscript-ai）— 使用指南（Phase 1）

> Phase 1 交付的是扩展骨架：**可用的设置页 + AI 连接能力**（OpenAI 兼容 API，支持 DeepSeek/Qwen/OpenAI/中转站/本地模型）。
> AI 对话与浏览器操控在 Phase 2+ 陆续加入。当前会话页/脚本池页是占位。

---

## 1. 环境要求

- **Node.js ≥ 20**（`node -v` 确认）
- **Chromium 浏览器**：Chrome / Edge / Brave（本文以 Chrome 为例）
- 一个 **OpenAI 兼容 API** 的账号与 Key（见第 4 节推荐配置）

## 2. 构建扩展

```bash
cd d:\workspace-mou8\ai-browser-extend

# 安装依赖（package.json 已配 postinstall 自动执行 wxt prepare）
npm install

# 生成生产构建
npm run build
```

构建产物在 `.output/chrome-mv3/`。

日常开发用 `npm run dev`（WXT 热更新，自动拉起浏览器并加载扩展）。

## 3. 在 Chrome 中加载

1. 打开 `chrome://extensions`
2. 右上角打开 **开发者模式**
3. 点击 **加载已解压的扩展程序**
4. 选择目录 `d:\workspace-mou8\ai-browser-extend\.output\chrome-mv3`
5. 工具栏出现拼图图标，把 "织雀AI脚本" **钉到工具栏**（方便点开）

改代码后重新加载：回到 `chrome://extensions`，点扩展卡片上的刷新按钮即可。

## 4. 配置 AI 服务（设置页）

点击工具栏扩展图标 → 打开侧边栏 → 左侧导航点 **设置**（齿轮图标）。

三个字段：

| 字段 | 说明 | 示例 |
|---|---|---|
| **Base URL** | OpenAI 兼容 API 的地址，**到 `/v1` 为止**（不带 `/chat/completions`） | `https://api.deepseek.com/v1` |
| **API Key** | 服务商发给你的密钥 | `sk-...` |
| **模型** | 模型 ID，照服务商文档填 | `deepseek-chat` |

常见服务商速查：

| 服务商 | Base URL | 模型示例 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 阿里 Qwen | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| 中转站 | 按站点文档（一般也是 `/v1` 结尾） | 站点提供的模型名 |
| 本地 Ollama | `http://localhost:11434/v1` | `qwen3:8b` |

**注意**：Ollama 需要允许扩展访问 localhost：`OLLAMA_ORIGINS=chrome-extension://*` 环境变量启动。

操作流程：

1. 填完三个字段 → 点 **测试连接**
   - 绿色「连接成功」= 配置可用
   - 红色错误信息会带上 HTTP 状态码与原因（15 秒超时）
2. 点 **保存**（配置存在本地 `chrome.storage.local`，不上传、不同步）

> 提示：测试连接会把当前表单里的 provider 配置一并保存。

**Agent 参数**：最大步数（工具调用循环上限），默认 25，Phase 2 生效。

## 6. 验证安装是否成功（冒烟清单）

1. `chrome://extensions` 里扩展已启用、无错误徽标
2. 点扩展图标 → 侧边栏打开
3. Service worker 控制台（扩展卡片 → "service worker" 链接）可见 `[vevscript] background started`
4. 设置页填好配置 → 测试连接 → 绿色成功提示
5. 关掉侧边栏再打开，配置仍在

## 8. 故障排查

| 症状 | 处理 |
|---|---|
| 测试连接报 `HTTP 401` | API Key 错误或过期 |
| 测试连接报 `HTTP 404` | Base URL 路径不对——检查是否该以 `/v1` 结尾、有没有多余路径 |
| 连接超时（15s） | 网络不通 / baseURL 不可达；本地模型检查服务是否启动 |
| 报「响应不是有效 JSON」 | 到达的不是 API 网关（可能是登录页/网关错误页），检查 Base URL |
| 点图标没反应 | 确认 `chrome://extensions` 里扩展已启用；重新加载扩展 |
| 重新加载后侧边栏白屏 | 关闭侧边栏重新打开；仍不行则重新加载扩展 |

## 9. 代码结构速览（改代码前先看这个）

```
entrypoints/
  background.ts        # Service Worker：消息中枢（MessageRouter + DEEP_OBSERVE_*）+ webRequest 观测接线
  sidepanel/           # React 侧边栏（App.tsx 三页路由）
components/            # UI 组件（chat/scripts/settings + ui 原子组件）
stores/ui.ts           # zustand 页面状态
agent/provider/        # OpenAI 兼容 provider：SSE 解析、流式、连接测试
storage/settings.ts    # 配置持久化（chrome.storage.local）
shared/                # 三环境共享类型（消息协议、ToolResult 等）
tests/                 # Vitest 测试（对应各模块）
```
